Arizona Games is a multiplayer game project I worked on as a full-time developer. My work was primarily focused on the technology surrounding the game, particularly the game launcher and backend infrastructure.

While the game itself is built around its own technology stack, the launcher and backend are responsible for connecting the different parts of the ecosystem together. This includes handling game distribution, updates, communication with backend services and the infrastructure required to support the client.

The launcher

One of the main areas I worked on was the Arizona Games launcher. The launcher acts as the entry point for players, taking care of the tasks that need to happen before the game itself starts.

This includes things such as version management, game updates, resource handling and communication with backend services. Building a launcher for an online game means that reliability matters: it needs to correctly handle different client versions, interrupted updates and various edge cases without getting in the player's way.

The backend

I also worked on the backend services supporting the launcher and game ecosystem. The backend provides the services required for clients to communicate with the infrastructure behind the game.

A major part of the work was making sure that the launcher and backend worked together reliably. Client-side functionality often depends on backend state, which means that seemingly simple features can require careful consideration of APIs, versioning, error handling and communication between services.

A launcher is more than a button that starts a game. It is the bridge between the player, the client and the infrastructure behind it.

Multiplayer infrastructure

Because Arizona Games is an online multiplayer project, backend infrastructure is an important part of the overall architecture. Clients cannot simply operate independently - they need to communicate with services that manage and provide information required by the game ecosystem.

This makes reliability and predictable communication particularly important. Failures need to be handled gracefully, and the client needs to be able to recover from problems such as unavailable services, interrupted downloads or outdated game versions.

Updates and distribution

Another important aspect of the launcher is game distribution and updating. Players should be able to start the launcher and get the correct version of the game without having to manually manage files or understand what changed between releases.

This requires more than simply downloading a new executable. The launcher has to understand what the client currently has, determine what needs to be updated and communicate with the backend to retrieve the required data.

Still very much in progress

Arizona Games was an evolving project, which made the work particularly interesting from an engineering perspective. Both the game and the surrounding infrastructure were continuously changing as new requirements appeared and existing systems were improved.

Working on the launcher and backend gave me the opportunity to deal with the less visible parts of an online game: infrastructure, APIs, distribution, updates, client-server communication and the tooling required to make the whole system work together reliably.
